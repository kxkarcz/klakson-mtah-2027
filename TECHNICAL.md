# Technical document

Team: `KLAKSON` · More than a Hack 2027, phase 1 · submission file `KLAKSON.csv`

## Summary

An unsupervised possession model. One hidden-Markov decoder over H / A / D takes three kinds of
evidence: ball-player geometry, Smart Tagging team votes, and a live/dead detector fitted on the
match itself. The live/dead evidence also uses a logistic regression trained on seven other
matches. No label of the provided match is used, and we made no hand labels for any match. The
submitted file (318 possessions, 121 stoppages) is regenerated byte for byte by one command
(section 6), and it passes the official validator.

## 1. Approach

The ranking scores whole possessions, not frames. A frame-by-frame method flickers, and each
flicker splits a possession in two. So the model works on segments. Per-frame evidence becomes
log-likelihoods, and a Viterbi decoder picks the label sequence, paying a fixed cost for every
change of state (2 nats between teams, 12 nats into or out of dead ball). Runs shorter than 1 s
(possession) or 2 s (stoppage) are merged into a neighbour.

**Dead ball.** A two-state (live / dead) HMM, fitted by EM on the match, observes the ball class
(fast, slow, stationary, out of bounds, or untracked, with the length of the gap) and the mean
speed of all tracked players. The players' speed is the one cue present on every frame. Activity
is taken as the larger of its present value and its value 3 s ahead, because players need several
seconds to get back up to speed after a restart. Two structural rules come from the data: the
two kick-off tags anchor the halves, and a sustained line-up with each team in its own half is
forced dead.

**Live/dead evidence.** A logistic regression (44 features, weights in `config/default.yaml`) trained
on the seven open DFL matches replaces the HMM's per-frame live/dead emissions. Its log-probabilities
are scaled by 0.25 because neighbouring frames are correlated. Six layout features get zero weight.
Training matches were damaged to resemble the provided tracking.

**Ownership.** For each frame with a ball, the distance from the ball to the nearest player of each
team gives a signed log-odds. It combines three factors: which team is clearly closer (a duel within
0.5 m counts for nothing), reach (full weight within 1.5 m, zero beyond 4 m), and calm (a ball at
passing speed next to a player does not show control).

**Smart Tagging.** Attacking phases vote for the tagged team and defending phases for its opponent.
Phases with no team and set pieces cast no vote, and phase edges are trimmed by 2 s. The vote weight
is calibrated on pseudo-labels from a first decoding pass that never sees the tags. Tagged intervals
are never copied into the output.

**Team shape.** A six-feature logistic model, fitted on the same pseudo-labels, uses team shape (width,
length, centroid separation, advance along the direction of attack). It applies only where the ball
is not tracked, tempered and capped so that shape alone needs several seconds to overturn a possession.

**Boundaries.** The start of a stoppage moves to a nearby ball exit (a ball leaving the pitch) found
between 3 s before and 1 s after the decoded start. In the submitted file 46 of 121 starts move, by a median of 0.16 s.

## 2. Assets and rejected approaches

| asset | used | how |
|---|---|---|
| tactical ATD (players + ball) | yes | every feature |
| tactical Smart Tagging | yes | soft team votes; kick-off tags anchor the halves; set-piece and transition tags only as an external check |
| tactical homography, video | no | the ATD is already in pitch coordinates; re-detecting the ball from video was out of reach in the time available |
| broadcast ATD and homography | no | a second ball track added too little (see below) |
| Metrica Sports sample games 1–3 | validation only | other matches |
| DFL open data, seven matches | training of the live/dead model; validation | other matches |
| SkillCorner open data, twenty matches | validation; two variants trained but switched off | other matches |

No pre-trained model is used in the submitted pipeline. A pre-trained person detector and pose model
were used only in a probe (below).

Each of the following was built behind a configuration flag, tested, and switched off because it did
not improve the label-free checks on this match:

* **Touch evidence** (3 nats per touch credited to the team at the ball). It helped on other matches
  with a cleaner ball track but not once the damage was fitted to the provided tracker, and it lowered
  agreement with tagging votes on this match (0.906 → 0.886).
* **Supervised ownership model** (logistic regression on ball-player geometry and touches, trained on
  seven DFL matches). It improved held-out matches, but on this match it agreed less with the tags
  (team after a tagged set piece: 14–15 of 27 against 18 with the hand-set evidence).
* **Snapping restarts or changes of possession** to ball events. Restarts within 3 s of tagged set
  pieces fell from 63% to 58%. Changes near tagged transitions fell from 46% to 33%.
* **Broadcast ball track as a second ball.** Synchronisation works, but frames where the players
  match cover only 29% of live play and fill 12% of the tactical ball's gaps. Even a more accurate ball
  on every frame would add only 0.010 spellF1 on average on other matches.
* **Players' feet from video** (pre-trained detector and pose model, probe only). The nearest ankle is
  hardly closer to the tracked ball than the tracking position is, so the error lies in the ball.
* **Supervised live/dead model trained on 27 matches.** It did better on held-out matches but found
  only 88 stoppages here and moved restarts away from the tagged set pieces. Its features
  picked up camera close-ups in SkillCorner data. The 7-DFL model was kept.
* **Semi-Markov decoder, in-play abstention, lag or offset correction of the ball.** Not built or not
  useful; the abstention rule would lower macroF1 with no gain in spellF1.

## 3. Possession rules implemented

* **Loose and contested balls.** Possession stays with the last team. A ball nobody can reach, a duel
  and an untracked ball all give zero evidence, so the decoder keeps its state.
* **Changes of possession.** A change costs 2 nats. A frame of clear, calm control is worth at most
  0.4 nats, so the opponent needs about a quarter of a second of clear control. A clean first touch
  counts, a ball flying past a player is down-weighted by speed, and a deflection is not enough.
* **Timing.** Viterbi places a change at the start of the controlling evidence.
* **Stoppages.** The ball is dead when the live/dead model says so for long enough to repay 12 nats:
  a long disappearance with walking players, a ball off the pitch, or a still ball with everyone
  standing. Dead-ball ownership is not modelled.
* **Restarts.** After a stoppage the first controlled touch decides. After a goal, the line-up rule
  sharpens the kick-off; other restarts use the activity look-ahead.
* **Abstention.** `X` before the first kick-off and from 60 s after the last sign of play. Never inside
  the match.

## 4. Data and validation

**No labelled data from this match was used.** The match-fitted components (HMM, tagging weight, shape
model) learn from the unlabelled match or from pseudo-labels produced by the algorithm.

Labelled datasets used to train a model:

| dataset | labelled by | amount | used for |
|---|---|---|---|
| DFL / IDSSE open data (Bassek et al., 2025; CC-BY 4.0) | the tracking provider, per-frame `BallStatus` | 7 matches | live/dead model in the submission |
| SkillCorner Open Data (MIT) | SkillCorner, per-frame possession group and phases | 20 matches | two variants, both switched off |

We made no labels by hand for any match. The providers' labels are published with their datasets,
and the publishers do not say how they were produced. None of these matches is the provided game, and
none is in this repository. The trained weights are numbers in `config/default.yaml` and cannot
reconstruct any of their data.

Sources (all public, accessible to the organisers):

* DFL / IDSSE: Figshare DOI `10.6084/m9.figshare.28196177` (mirror `huggingface.co/datasets/pysport/idsse-data`),
  seven Bundesliga matches, tracking at 25 fps.
* SkillCorner Open Data: `github.com/SkillCorner/opendata`, twenty A-League 2024/25 matches.
* Metrica Sports sample data: `github.com/metrica-sports/sample-data`, three matches.

`scripts/train_liveness.py` regenerates the live/dead weights from local copies of the DFL matches.

**Other matches, used for validation and for choosing the switch cost.** Metrica Sports sample games
1–3 (events give the labels, derived mechanically in `validation/metrica.py`) and the seven DFL matches
(provider labels) are scored with the official scorer. Metrica game 3 was also used to time
boundary cues.

* The switch cost of 2 was chosen on Metrica game 3 and confirmed on games 1 and 2. On DFL matches
  the cost 1 is better by 0.01–0.04, inside the scorer's noise band on two of three matches, so the
  value was kept. The old value 6 loses 0.06–0.09 on every match.
* Each match was also scored on a degraded copy of its ball track, because the provided ball is mostly
  missing while play is dead. Degradation was fitted to the provided tracker on one DFL match and
  checked on nine others.
* Stoppages are nearly solved on these matches. Almost all the loss is in short possessions and changes
  of team, which is why the remaining work is evidence for brief possessions.

**Checks on this match.** Smart Tagging is not used for these measures, only as an independent check:

| measure | value |
|---|---|
| restarts within 1 s / 3 s of the typical position inside a set-piece tag (59 tags) | 36% / 66% |
| team after a team-tagged set piece agrees with the tag (27 tags) | 85% |
| tracking-only decode vs tagging votes | 0.767 |
| final decode vs tagging votes | 0.889 |
| possessions / stoppages | 318 / 121 |

Agreement with tagging votes falls when the switch cost is lowered, but tagged phases are padded windows
of 20–30 s, so this measure rewards long possessions. It was used as a check, not as the criterion.

## 5. Limitations

* **No ground truth for this match.** Every choice rests on indirect evidence: a few automatic tags
  (59 set pieces, 24 transitions) and other matches. On the SkillCorner matches, the closest to the
  provided tracking, this pipeline scores about 0.38 against 0.25 for the official baseline.
* **Boundaries without a ball event.** Most stoppage starts and about half of the restarts have no ball
  event nearby. Their position comes from player activity and gap length, good to a second or two.
* **Short possessions.** Single touches and intercepted passes are the main source of error.
* **Live play with a lost ball** is treated as dead unless the players are clearly running.
* **A ball thrown around during a stoppage** can produce a spurious short possession.
* **Height is invisible.** A high ball crossing a defender in 2-D looks like a touch; only the speed
  factor and the switch cost protect against it.
* **Half anchors depend on the kick-off tags.** Without both, pre-match warm-up may be labelled live.

## 6. Reproduction

See [README.md](README.md). In short:

```bash
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.lock
.venv/Scripts/python -m pip install --no-deps .
export MTAH_DATA_DIR=/path/to/data
.venv/Scripts/python -m possession run --config config/default.yaml --out outputs/KLAKSON.csv
```

Expected SHA-256: `34cc2bd6a62af0e6264d5a0d71f28f0621504f403357b621828b8d93e9d75bbd`
(identical with and without the cache; Python 3.11.9, Windows 11).
